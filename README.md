# 🤫 Whisper Bot — эфемерные сообщения в Telegram

Два способа отправить шёпот:

1. **Inline-режим, без добавления бота в чат** — работает из любого чата:
   ```
   @secretnobot Привет @verifure
   ```
   Получатель нажимает «Прочитать 🔓» и видит текст во всплывающем окне
   (`answerCallbackQuery(show_alert=True)`). Остальные получают «🤐 Это не тебе».

2. **Команда `/whisper`, бот состоит участником группы** — здесь бот пробует
   доставить **настоящее эфемерное сообщение** (Bot API 10.2/10.3), а не
   просто всплывающее окно:
   ```
   /whisper Привет @verifure
   ```

Весь бот — **один файл `main.py`**, без пакетов и папок, специально, чтобы
структура репозитория никогда не могла сломать деплой.

---

## Почему два способа, а не один

Это платформенное ограничение Telegram, не решение из соображений удобства.

`sendMessage` **всегда** требует `chat_id` — даже с параметром
`ephemeral_message_parameters` исключений нет (подтверждено официальной
документацией метода). А у сообщений, отправленных через inline-режим,
`callback_query` **никогда** не несёт `chat_id` — только `inline_message_id`.
Это свойство того, как сообщение было создано, а не того, состоит ли бот в
чате сейчас. Поэтому:

- inline-режим (способ 1) физически не может использовать настоящие
  эфемерные сообщения — для него всплывающее окно единственный путь;
- только когда карточка создана обычным `send_message` внутри чата, где бот
  состоит участником (способ 2, команда `/whisper`), боту известен `chat_id`,
  и появляется возможность настоящей эфемерной доставки.

## Как работает доставка (способ 2)

| Шаг | Метод / объект Bot API |
|---|---|
| Публикация карточки | `send_message` с кнопкой `InlineKeyboardMarkup` |
| Нажатие «Прочитать» | `callback_query` — теперь есть `message.chat.id` |
| Попытка эфемерной доставки | `sendMessage` с `ephemeral_message_parameters: {receiver_user_id, callback_query_id, replace_callback_query_message}` |
| Вызов в обход версии библиотеки | `Bot.do_api_request("sendMessage", api_kwargs=kw)` |
| Проверка успеха | сервер обязан вернуть `ephemeral_message_id` в ответе |
| Откат | если поля нет — сервер прислал обычный ответ (функция ещё не активна для этого чата) → `answerCallbackQuery(show_alert=True)` |

`do_api_request` — официальный механизm python-telegram-bot для вызова
методов Bot API, которые установленная версия библиотеки может ещё не знать
нативно; ровно этот приём использован в референсном проекте `verifure-game`.
Условие валидности запроса по правилам Bot API — передан `callback_query_id`
(ответ на нажатие кнопки, в течение ~15 секунд) — выполнено всегда, так как
попытка идёт именно в обработчике нажатия.

**Честно о статусе функции**: успех проверяется не по отсутствию ошибки, а по
факту — вернул ли сервер `ephemeral_message_id`. Если Telegram ещё не включил
эту функцию для конкретного чата или аккаунта, сервер может молча прислать
обычный ответ без этого поля — тогда бот откатывается на всплывающее окно, и
доставка всё равно происходит, просто не в новом формате.


Все файлы — в корне репозитория, без вложенных папок.

---

## 1. Настройка бота в @BotFather

1. `/newbot` → получите **BOT_TOKEN**.
2. `/setinline` → включите inline-режим (нужен для способа 1).
3. Для способа 2 — просто добавьте бота в нужную группу обычным образом.
   Команды всегда доходят до бота, даже при включённом режиме приватности
   группы, специальных настроек privacy mode не требуется.
4. Опционально `/setinlinefeedback` → `Disabled`.

---

## 2. Локальный запуск

```bash
git clone <ваш-репозиторий> && cd secret-whisper-bot
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # впишите BOT_TOKEN
export $(grep -v '^#' .env | xargs)
python main.py
```

---

## 3. Деплой на Railway

1. Залейте код на GitHub — файлы в корне репозитория, без подпапки.
2. New Project → Deploy from GitHub repo → Variables → `BOT_TOKEN`.
3. Проверка структуры перед пушем:
   ```bash
   git ls-files | sort
   ```
   Должны быть `main.py`, `requirements.txt`, `Procfile` — без вложенных папок.

### Redis (рекомендуется)

`+ New → Database → Add Redis`, затем в сервисе бота:
```
REDIS_URL = ${{Redis.REDIS_URL}}
```
Без него и шёпоты, и вообще всё состояние теряются при каждом редеплое.

## 4. Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | **Обязательно.** Токен от @BotFather |
| `REDIS_URL` | — | Redis для постоянного хранения |
| `WHISPER_TTL` | `604800` | Сколько секунд живёт шёпот (7 дней) |
| `BURN_AFTER_READING` | `false` | Сжигать после первого прочтения получателем |
| `NOTIFY_SENDER` | `true` | Писать автору в ЛС о прочтении |
| `MAX_TEXT_LEN` | `200` | Лимит длины текста |
| `EPHEMERAL_ENABLED` | `true` | Пробовать настоящие эфемерные сообщения для `/whisper` |
| `REPLACE_CALLBACK_MESSAGE` | `true` | Заменять карточку эфемерным сообщением у читающего |
| `USE_WEBHOOK` | `false` | Webhook вместо polling |
| `PUBLIC_URL` | авто из `RAILWAY_PUBLIC_DOMAIN` | Базовый URL для webhook |

---

## 5. Приватность

* Текст шёпота никогда не попадает в сообщение чата и в `callback_data`.
* В логи содержимое не пишется.
* Записи автоматически удаляются по TTL, а при `BURN_AFTER_READING=true` —
  сразу после прочтения.
* Это не end-to-end шифрование: у владельца сервера технически есть доступ к
  хранилищу.
